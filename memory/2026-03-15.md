# 2026-03-15

## MiroFish Audit -> Aeternus Scenario Bridge

- Conducted a deep architecture audit of the open-source MiroFish repo and mapped it against Aeternus.

- Main conclusion:
  - MiroFish is not a giant always-on world scout in the OSS repo
  - it is a compiler pipeline from:
    - files + requirement
    - ontology
    - graph
    - actor profiles
    - runtime config
    - simulation
    - graph writeback
    - query/report

- Aeternus comparison:
  - stronger on ambient sensing, AKG memory, and learning
  - weaker on question-conditioned compilation into a scenario runtime

- New planned bridge:
  - `Scout Compiler`
    - after scouts
    - shadow sidecar initially
    - outputs daily scenario artifacts / `Event Card` JSON
  - `Scenario Retriever`
    - separate from compiler
    - searches internal state first
    - reports `COMPLETE / PARTIAL / MISSING`
    - on gaps, lists missing evidence and waits for user
    - does not auto-run external retrieval

- Product insight:
  - every daily run should become a daily scenario
  - cross-scout relationships should be captured as first-class artifacts

- Pipeline/CLI wiring:
  - `tradingagents/dealflow/pipeline.py`
    - runs the scout compiler as a shadow sidecar at the end of `discover()`
    - writes daily artifacts:
      - `event_cards.json`
      - `coverage_precheck.json`
      - `scout_compiler_debug.json`
      - `akg_writeback_candidates.json`
      - `scout_quality_daily.json`
  - `cli/commands/dealflow.py`
    - `discover` now prints scenario/scout-quality summaries
    - new `scenario-retrieve` CLI command added

- Key `v1` behavior:
  - no AKG mutation
  - no external fetches in retriever
  - no automatic scout reruns
  - broad “what matters today?” retrieval now selects top-ranked Event Cards instead of matching every card
  - grouped scout-quality metrics now count grouped source records, including manual X-feed

- Important bug fixed during live verification:
  - `discover()` still referenced an uninitialized `_iv_results` while building scout audit
  - that caused `_build_scout_audit()` to fail silently, which suppressed breakout and earnings-options evidence from the new scenario sidecar
  - fixed by initializing `_iv_results` before the audit build and by normalizing scout-audit payloads through JSON-safe serialization
