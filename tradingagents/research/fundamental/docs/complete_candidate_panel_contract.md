# Complete Candidate Panel Contract

## Purpose

The complete candidate panel is the canonical pre-LLM-to-Top15 review artifact
for fundamental runs. It keeps the full candidate panel, official Top15
annotations, and shadow refill review annotations in one validated CSV so
operators can review the same candidate universe that fed final selection.

Schema version: `fundamental_complete_panel_v1` from
`tradingagents/research/fundamental/src/panel/schema.py`.

Canonical producer:
`tradingagents.research.fundamental.src.panel.exporter.build_complete_panel`
under `tradingagents/research/fundamental/src/panel/`.

## One-command usage

Standalone build:

`fundamental-build-complete-panel --run-root <daily-run-root> --quarter <YYYYQ#> --output-root <output-root>`

Daily integrated build:

`fundamental-run-today --emit-complete-panel`

Use `--complete-panel-output-root <output-root>` when the complete panel should
land outside the daily run root.

## Required fields

Every row must conform to `REQUIRED_COMPLETE_PANEL_COLUMNS` for schema version
`fundamental_complete_panel_v1`. Required groups include:

- identity: quarter, ticker, symbol, CIK, company title, CIK status
- price/provenance: trade date, entry price, source file, build ID/timestamp,
  feature schema metadata, source artifact provenance
- pre-LLM financial inputs and derived scores
- Tier 0-4, HP, repricing momentum, theme, LLM, final score, Top15, shadow
  refill, and diagnostic return fields

Required financial/value blanks must carry an allowed missing reason in the
matching `*_missing_reason` field.

## Allowed missing reasons

Default allowed reasons:

- `source_fact_unavailable_as_of`
- `not_populated_by_normalize`
- `not_applicable`

`companyfacts_not_supplied` is allowed only when the build explicitly enables
missing financials, currently through `allow_missing_financials` or the CLI
equivalent.

## Output files

CSV convention:

`fundamental_complete_prellm_to_top15_<quarter>.csv`

Sidecars in the same requested output root:

- `fundamental_complete_prellm_to_top15_<quarter>_manifest.json`
- `fundamental_complete_prellm_to_top15_<quarter>_columns.json`
- `fundamental_complete_prellm_to_top15_<quarter>_validation.json`

In daily runs, Gate 11 records these paths as:

- `complete_panel_csv`
- `complete_panel_manifest`
- `complete_panel_columns`
- `complete_panel_validation`

## Validation gates

The exporter validation must reject or flag:

- missing required columns
- required blanks without an allowed missing reason
- duplicate ticker-quarter rows
- flag values outside `0` or `1`
- quarter coverage gaps
- Top15 or shadow refill identity mismatches
- selection-source leakage into candidate features
- non-canonical prior panels

Raw legacy `Growth/` combined CSVs passed directly as `--prior-panel` fail with
`prior_panel_not_canonical`.

## Relationship to Top10+Plus5+shadow refill

The panel includes the full candidate universe plus official Top15 annotations
and shadow refill review annotations. It does not replace selector ownership.
Top10 core, Plus5 sleeve, and shadow refill selection remain generated by the
canonical selector logic; this panel records those outcomes beside the complete
candidate rows for review, audit, and backtest continuity.

## Legacy `Growth/` status

Growth/ scripts are historical research artifacts.
New publishable complete panels must come from `src.panel.exporter`.

`Growth/` combined CSVs are historical/reference inputs only. They are not
output owners for publishable complete panels. Any migration from raw legacy
combined CSVs into canonical complete panels must be explicit and must pass the
canonical manifest, columns, and validation sidecar contract before the result
can be used as a prior panel.
Legacy combined CSVs can be imported only by explicit migration tooling, not directly as `--prior-panel`.
