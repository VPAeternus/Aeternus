# Executive Summary

## What We're Building

**Aeternus** is a next-generation investment research and social platform that combines the real-time intelligence of X/Twitter, the social dynamics of Facebook, and the accessibility of Robinhood—purpose-built for serious investors who want an edge.

Unlike existing platforms that offer fragmented tools, Aeternus delivers a **unified investment intelligence ecosystem** where:
- Proprietary research algorithms surface opportunities before they trend
- Users build, track, and share custom investment indexes
- A transparent ratings system with verifiable track records builds trust
- A social layer connects investors around ideas, not noise

## The Problem

Today's retail and sophisticated investors face a fragmented landscape:

| Platform | Strength | Weakness |
|----------|----------|----------|
| Bloomberg Terminal | Comprehensive data | $24K/year, steep learning curve |
| Robinhood | Accessible trading | Zero research depth, gamification |
| Twitter/X | Real-time sentiment | Noise-to-signal ratio, no accountability |
| Seeking Alpha | Quality research | Paywall, no portfolio integration |
| Reddit (WSB) | Community energy | Memes > analysis, pump-and-dump risk |

**No single platform combines:**
- Institutional-grade research
- Social accountability
- Portfolio building tools
- Performance transparency

## The Solution

Aeternus creates an **Investment Intelligence Network** where:

1. **Research is actionable** — Not just information, but scored recommendations
2. **Performance is transparent** — Every rating has a public track record
3. **Community is accountable** — Follow investors with proven results
4. **Tools are powerful** — Build custom indexes, compare to benchmarks, execute strategies

## Market Opportunity

- **$10T+** Assets held by retail investors in US alone
- **120M+** Active retail traders post-pandemic
- **73%** of Gen Z/Millennials want social investing features
- **$0** platforms combine research + social + transparency at scale

## Vision Statement

> *"To democratize institutional-quality investment intelligence while building the most trusted investment community in the world."*

```
AETERNUS SCORE = 
  (Fundamental Score × 0.30) +
  (Technical Score × 0.25) +
```

```yaml
  ├── Short-Term (Working Memory)

  │
  └── Semantic (Knowledge Base)
```

## Database Design

### Core Entities

```sql
-- Users
CREATE TABLE users (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    email VARCHAR(255) UNIQUE NOT NULL,
    username VARCHAR(50) UNIQUE NOT NULL,
    display_name VARCHAR(100),
    avatar_url TEXT,
    bio TEXT,
    is_verified BOOLEAN DEFAULT FALSE,
    is_premium BOOLEAN DEFAULT FALSE,
    created_at TIMESTAMPTZ DEFAULT NOW(),
    updated_at TIMESTAMPTZ DEFAULT NOW()
);

-- Indexes (User-created)
CREATE TABLE indexes (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id UUID REFERENCES users(id),
    name VARCHAR(100) NOT NULL,
    description TEXT,
    is_public BOOLEAN DEFAULT FALSE,
    rebalance_frequency VARCHAR(20),
    created_at TIMESTAMPTZ DEFAULT NOW(),
    updated_at TIMESTAMPTZ DEFAULT NOW()
);

-- Index Holdings
CREATE TABLE index_holdings (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    index_id UUID REFERENCES indexes(id),
    symbol VARCHAR(10) NOT NULL,
    weight DECIMAL(5,4) NOT NULL, -- 0.0000 to 1.0000
    created_at TIMESTAMPTZ DEFAULT NOW()
);

-- Ratings (Aeternus Official)
CREATE TABLE ratings (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    symbol VARCHAR(10) NOT NULL,
    rating VARCHAR(20) NOT NULL, -- STRONG_BUY, BUY, HOLD, SELL, STRONG_SELL
    price_target DECIMAL(10,2),
    confidence INTEGER CHECK (confidence BETWEEN 1 AND 5),
    thesis TEXT,
    risks TEXT,
    catalysts TEXT,
    price_at_rating DECIMAL(10,2),
    is_active BOOLEAN DEFAULT TRUE,
    created_at TIMESTAMPTZ DEFAULT NOW(),
    updated_at TIMESTAMPTZ DEFAULT NOW()
);

-- Social Posts
CREATE TABLE posts (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id UUID REFERENCES users(id),
    content TEXT NOT NULL,
    post_type VARCHAR(20), -- TEXT, CHART, INDEX, TRADE_IDEA
    symbols VARCHAR(10)[], -- Array of mentioned tickers
    index_id UUID REFERENCES indexes(id), -- If index post
    likes_count INTEGER DEFAULT 0,
    comments_count INTEGER DEFAULT 0,
    created_at TIMESTAMPTZ DEFAULT NOW()
);

-- Follows
CREATE TABLE follows (
    follower_id UUID REFERENCES users(id),
    following_id UUID REFERENCES users(id),
    created_at TIMESTAMPTZ DEFAULT NOW(),
    PRIMARY KEY (follower_id, following_id)
);
```

# Architectural Principles: Lessons from Building AI Agents for Financial Services

*Based on lessons from Nicolas Bustamante (Fintool) - two years building AI agents for professional investors*

## Core Philosophy

> *"The model is not your product. The experience around the model is your product."*

These principles are battle-tested in production with professional investors making million-dollar decisions.

---

## Principle 1: The Sandbox Is Not Optional

### Why It Matters
LLMs executing multi-step operations can cause catastrophic damage. Without isolation, a prompt asking to "clean up temporary files" could execute `rm -rf /`.

### Aeternus Architecture
```
┌─────────────────────────────────────────────────────────────┐
│              PER-USER SANDBOX ISOLATION                     │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│   User Sandbox:                                             │
│   ├── /private (read/write) - User's data                   │
│   ├── /shared (read-only) - Organization standards          │
│   └── /public (read-only) - Platform skills                 │
│                                                             │
│   Security:                                                 │
│   ├── AWS ABAC credentials scoped to S3 prefixes           │
│   ├── User A cannot access User B's data                    │
│   ├── Pre-warming: Spin up on user type                    │
│   └── 600s timeout (extendable on activity)                 │
└─────────────────────────────────────────────────────────────┘
```

---

## Principle 2: Context Is the Product

### Why It Matters
*"Normalizing financial data is 80% of the work."* Anyone can call an LLM API. Not everyone has normalized decades of financial data.

### Data Normalization Pipeline
```
┌─────────────────────────────────────────────────────────────┐
│                   NORMALIZATION LAYER                       │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│   Input Sources              Normalized To                  │
│   ─────────────────────────────────────────────────────     │
│   SEC Filings          →    Markdown (section-by-section)   │
│   Earnings Calls       →    Markdown (speaker turns)        │
│   Financial Statements →    Clean CSV/markdown tables       │
│   Market Data          →    JSON with standardized fields   │
│   Research Reports     →    Markdown with citations         │
│   News Articles        →    Paragraph-level chunks          │
│                                                             │
│   Metadata Standards:                                        │
│   Every document has meta.json with:                        │
│   - Ticker resolution (FB → META, TWTR → X)                 │
│   - Document type (10-K, 10-Q, 8-K, earnings call)          │
│   - Fiscal period (with fiscal calendar normalization)      │
│   - Section targeting (Item 1, CFO remarks, etc.)           │
└─────────────────────────────────────────────────────────────┘
```

### Chunking Strategy
| Document Type | Chunking Approach |
|--------------|-------------------|
| 10-K/10-Q | By regulatory section (Item 1, 1A, 7, 8...) |
| Earnings Calls | By speaker turn (CEO, CFO, Q&A by analyst) |
| Press Releases | Single chunk (usually small) |
| News Articles | Paragraph-level |
| 13F Filings | By holder, position changes quarter-over-quarter |

---

## Principle 3: The Parsing Problem

### Why It Matters
SEC filings are adversarial - designed for legal compliance, not machine reading.

### Quality Gates
```yaml
Table Extraction Confidence Thresholds:
  Cell boundary accuracy:  >90%
  Header detection:        Verify header rows
  Numeric parsing:         "$1,234" → 1234 (not text)
  Unit inference:          Millions? Billions? Per share?

Low-confidence extractions:
  - Do NOT enter agent context
  - Flag for human review
  - "Garbage in, garbage out"
```

### Fiscal Period Normalization
```
Critical: "Q1 2024" is ambiguous
- Calendar Q1: January-March 2024
- Apple's fiscal Q1: October-December 2023
- Microsoft's fiscal Q1: July-September 2023

Solution: Maintain fiscal calendar database for 10,000+ companies
Every date reference → Absolute date ranges
```

---

## Principle 4: Skills Are Everything

### Why It Matters
*"The model is not the product. The skills are now the product."*

### Skill Architecture
```
┌─────────────────────────────────────────────────────────────┐
│                      SKILL ECOSYSTEM                        │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│   A skill is a markdown file:                               │
│   ───────────────────────────────────────────────────        │
│   # skill_name                                              │
│   ## When to Use                                            │
│   Description of when to apply this skill                   │
│                                                             │
│   ## Instructions                                           │
│   Step-by-step guidance for the agent                       │
│                                                             │
│   ## Industry Guidelines                                    │
│   Sector-specific methodologies                             │
│                                                             │
│   Priority: private > shared > public                       │
│   /private/skills/dcf/SKILL.md  → User custom               │
│   /shared/skills/dcf/SKILL.md   → Organization              │
│   /public/skills/dcf/SKILL.md   → Aeternus default          │
└─────────────────────────────────────────────────────────────┘
```

### Skills Library
| Category | Skills |
|----------|--------|
| Valuation | DCF, LBO, Comparable Companies, Precedent Transactions |
| Analysis | Technical Analysis, Wyckoff Patterns, Fundamentals |
| Research | Earnings Analysis, SEC Filing Analysis, Credit Analysis |
| Portfolio | Index Construction, Rebalancing, Risk Analysis |

### Benefits
1. **Non-engineers can create** - Analysts write skills
2. **No deployment needed** - Immediate effect on change
3. **Auditable** - Read skill, understand behavior
4. **Shadowing** - Users override without modifying originals

## Principle 5: The Model Will Eat Your Scaffolding

### Why It Matters
Models improve every few months. Elaborate scaffolding becomes obsolete.

### Design for Obsolescence
```
Prediction: In 2 years, basic skills will be one-liners
  "Generate a 20-tab DCF" → Model knows what this means

Strategy:
- Write skills
- Delete them when unnecessary  
- Build new ones for harder problems
- Send detailed feedback to AI labs

But frontier keeps moving:
- Multi-step valuations with segment analysis
- Automated backtesting
- Real-time portfolio monitoring
```

## Principle 6: S3-First Architecture

### Why It Matters
*"S3 for files is a better database than a database."*

### Architecture Pattern
```
┌─────────────────────────────────────────────────────────────┐
│                   S3-FIRST ARCHITECTURE                     │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│   Writes → S3 (source of truth)                             │
│            ↓                                                │
│   Lambda trigger                                            │
│            ↓                                                │
│   PostgreSQL (fs_files table) - fast queries               │
│                                                             │
│   Why S3?                                                   │
│   - 11 nines durability                                    │
│   - Versioning (audit trails)                               │
│   - Human-readable YAML                                     │
│   - Cost effective                                          │
└─────────────────────────────────────────────────────────────┘
```

### User Memories Pattern
```
Every user has: /private/memories/UserMemories.md

Users write: "I focus on small-cap value stocks"
Agent sees: On every conversation, adapts accordingly

No migrations, no schema changes - just markdown
```

## Principle 7: Temporal for Long-Running Tasks

### Why It Matters
Complex tasks (5+ minutes) break with server restarts, closed tabs, network issues.

### Implementation
```yaml
Temporal Workflows Handle:
- Worker crashes (automatic retry)
- Cancellation with heartbeats
- State persistence across failures

Worker Types:
- Chat workers: User-facing, 25 concurrent activities
- Background workers: Async, 10 concurrent activities

Scale independently based on traffic patterns
```

---

## Principle 8: Real-Time Streaming

### Why It Matters
Professional investors won't wait 30 seconds staring at a loading spinner.

### Architecture
```
Agent → SSE Events → Redis Stream → API → Frontend

Key Innovation: Delta updates, not full state
"Append these 50 characters" vs "Complete response so far"
```

### Interactive Workflows
```
AskUserQuestion tool:
- Agent pauses mid-workflow
- Presents options to user
- User picks or types answer
- Conversation resumes

Transforms agents from black boxes to collaborative tools
Essential for high-stakes financial decisions
```

---

## Principle 9: Evaluation Is Not Optional

### Why It Matters
Generic NLP metrics (BLEU, ROUGE) don't work for finance. A response can be semantically similar but have wrong numbers.

### Test Categories
```yaml
1. Ticker Disambiguation (50+ test cases):
   - "Apple" → AAPL (not APLE)
   - "Meta" → META (not MSTR)
   - Handle ticker changes (FB → META, TWTR → X)

2. Fiscal Period Hell (200+ test cases):
   - "Last quarter" on Jan 15 means different things
   - 10,000+ company fiscal calendar

3. Numeric Precision:
   - "$4.2B" vs "4,200M" vs "4.2 billion"
   - Units must be explicit

4. Adversarial Grounding (50 test cases):
   - Inject fake numbers, verify real source citation
   - Hallucination resistance testing
```

### Eval-Driven Development
```
Every skill has companion eval
- DCF skill: 40+ test cases
- Total: 2,000+ test cases across categories

PR blocked if eval score drops >5%
```

## Principle 10: Production Monitoring

### Observability Stack
```
Error → Auto-filed GitHub Issue
        - Priority:high for paying customers
        - Links to traces and workflows
        - Full context for debugging
```

### Model Routing
```yaml
By complexity:
- Simple queries: Fast/cheap model
- Complex analysis: Best/expensive model

Enterprise users: Always get best model
```

# Visual Feedback Loop System

*Based on lessons from CJ Hess and the AI agent community*

## The Problem: Text-Based Feedback Is Broken

Traditional AI agent workflows suffer from a fundamental problem: **agents can't see what you see**.

```
The Feedback Loop From Hell:
You: "The button should be more to the left."
Claude: [Makes a change]
You: "It's still wrong."
Claude: [Tries again]
You: "Not quite right... can you try again?"
[Repeat indefinitely]
```

### Why Text Fails

| Approach | Claude Can See? | Precise Coordinates? | Component-Level? |
|----------|-----------------|---------------------|------------------|
| Text descriptions | ❌ No | ❌ No | ❌ No |
| Screenshot paste | ✅ Yes | ❌ No | ❌ No |
| Chrome extension | ✅ Yes | ❌ No | ❌ No |
| **Visual Feedback Loop** | ✅ Yes | ✅ Yes | ✅ Yes |

## The Solution: Visual Annotation System

### Core Workflow

```
1. Capture     → Screenshot or screen recording

6. Verify      → Capture new screenshot, repeat if needed
```

# TradingAgents Framework

*Based on TauricResearch/TradingAgents (arXiv:2412.20138)*

## Overview

TradingAgents is a **multi-agent LLM financial trading framework** that mirrors dynamics of real-world trading firms. By deploying specialized agents (fundamental analysts, sentiment experts, technical analysts, traders, risk management), the platform collaboratively evaluates market conditions and informs trading decisions.

## Agent Specializations

### 1. Fundamentals Analyst
- Analyzes income statements, balance sheets, cash flow
- Calculates P/E, DCF, EBITDA multiples
- Identifies financial red flags
- Evaluates management quality

### 2. Sentiment Analyst
- Monitors X/Twitter finance communities
- Tracks Reddit (WSB, r/investing) sentiment
- Analyzes Seeking Alpha article sentiment
- Detects unusual social chatter volume

### 3. Technical Analyst
- MACD, RSI, Bollinger Bands interpretation
- Wyckoff accumulation/distribution phases
- Support/resistance identification
- Volume profile analysis

### 4. Researcher Team (Bullish + Bearish)
- Critical assessment through structured debate
- Balances potential gains vs inherent risks
- Challenges analyst assumptions

### 5. Trader Agent
- Composes reports from all agents
- Determines timing and trade sizing
- Aligns with Aeternus ratings system
- Generates actionable recommendations

### 6. Risk Management Team
- Evaluates portfolio risk (VaR, Sharpe)
- Assesses volatility and liquidity
- Reviews stop-loss levels
- Checks concentration limits

### 7. Portfolio Manager
- Final approval/rejection of trades
- Sends orders to exchange
- Maintains index alignment
